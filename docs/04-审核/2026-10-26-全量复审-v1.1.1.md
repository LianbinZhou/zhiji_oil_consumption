最要紧的四条：

## 一、Blocker

### [B1] 优惠金额从未落库（v1.1.0 主功能静默失效）

- **位置**：`lib/features/records/providers/records_provider.dart:82`（参数）、`:94-107`（Companion）、`:122`（参数）、`:130-143`（Companion）
- **证据**：
  ```
  $ grep -n "discount" lib/features/records/providers/records_provider.dart
  82:    double discount = 0,        ← 只在参数列表里
  122:    double discount = 0,        ← 同上

  # addRecord 构造的 Companion（:94-107）：
  quantity / amount / unitPrice / odometer / isFull / isLightOn /
  fuelType / chargeMethod / energyType / stationName / notes / createdAt
  ↑ 没有 discount

  # updateRecord 构造的 Companion 同样没有
  ```
  对照：界面的确把值传进来了（`record_dialog.dart:313` `discount: discount`），数据库也有这一列（`tables.dart:144` `discount.withDefault(0.0)`，schemaVersion 5 迁移里也建了）。
- **原因**：典型"加了一半"——UI、模型、DB 列、导出/导入全做了，唯独写入路径漏了一个字段。
- **影响**（真机测试为什么发现不了）：
  - 实付金额 `amount` 是**另一个字段**（`_calculatePrice()` 算出来的 paid），所以花费、每公里成本、月度统计全部正确；
  - 用户填的"优惠 43"在保存时被丢掉，库里记 0；
  - **再次编辑这条记录时**，`_discountController` 从 `record.discount`（=0）回填 → 输入框变空，用户会看到"我明明填过 43"。这是唯一的可察觉点，但只有回头编辑才会发现；
  - 于是 v1.1.0 的"机显 ≠ 实付"实际退化成"只有实付"，机显金额 `amount + discount` 永远算不回来。
- **建议**：两处 Companion 各加一行 `discount: drift.Value(discount),`；补一条测试（见 m7）；发版说明里提醒"1.1.0 期间录入的优惠未被保存，如需可重新编辑补录"。
- **验证方法**：录一条 数量 100 × 单价 7.5、优惠 43 的记录 → 用 DB 工具（或导出 JSON）看 `discount` 是 0 还是 43。**导出的 JSON 里就能看到（`exportToJson` 是带着这列的）**，不用连数据库。

## 二、Major

### [M1] 编辑历史油品标号时下拉匹配不到（debug 崩溃 / release 空白）

- **位置**：`lib/features/records/presentation/record_dialog.dart:68-73`（选项）、`:83-95`（编辑态回填）；`lib/shared/utils/fuel_type_label.dart:28`（`normalizeFuelType` 从未被调用）
- **证据**：
  ```
  # v1.0.7 之前（git show 1f73d1f^:…/record_dialog.dart）
  63:  static const List<String> _fuelTypes = ['92#', '95#', '98#', '0#柴油', '其他'];

  # 现在
  static const List<String> _fuelTypes = ['92#','95#','98#','0#','-10#','-20#','-35#','其他'];

  # 编辑态只做直接赋值，没有归一化：
  _selectedFuelType = widget.record!.fuelType;      // 可能是 '0#柴油' / '93#' / '97#'

  # DropdownButtonFormField
  initialValue: _selectedFuelType
  items: _fuelTypes.map(...)                        // 不含 '0#柴油'
  ```
  `normalizeFuelType(raw) => fuelTypeLabel(raw)` 只把 `0#` 补成 `0#柴油`，**方向与现在的设计相反**（下拉里存 `0#`、显示才加"柴油"），而且全项目没有任何调用点。
- **影响**：
  - 用过 v1.0.0–v1.0.6 并选过"0#柴油"的记录，或从旧备份/小熊油耗导入的 `93#`/`97#`/`0#柴油` 记录，点开编辑 → `DropdownButton` 的 `initialValue` 不在 items 中 → **debug 构建直接断言失败**；release 构建下拉显示空白（hint），用户不改就保存则原值保留（不丢数据），但会以为"油品没填"。
  - 纯电车不受影响（走充电方式分支）。
- **建议**（3 行）：构造 items 时把当前值补进去
  ```dart
  final fuelItems = {..._fuelTypes, if (_selectedFuelType != null) _selectedFuelType!}.toList();
  ```
  顺手删掉 `normalizeFuelType`（死代码且语义已反）。
- **验证方法**：把一条记录的 `fuel_type` 改成 `0#柴油`，点开编辑（debug 包会立刻断言报错）。

### [M2] 纯电车统计页出现无意义/误导的两格

- **位置**：`lib/features/statistics/presentation/statistics_screen.dart:236`（总加油量）、`:277-283`（油价范围）；对照 `statistics_provider.dart:197-200`
- **证据**：
  ```dart
  // 界面：无条件渲染
  236: _buildStatItem(context, '总加油量', '${UnitConverter.volume(stats.totalFuel, ...)}…L', …)
  281: '¥${stats.minPricePerLiter.toStringAsFixed(2)} - ¥${stats.maxPricePerLiter.toStringAsFixed(2)}/L'

  // 数据：只统计汽油
  final minPrice = await database.getMinUnitPrice(vehicleId, EnergyTypes.gasoline) ?? 0;
  ```
- **影响**：纯电车（`energy_type = electric`，没有加油记录）的统计页会显示
  - `总加油量 0 L`
  - `油价范围 ¥0.00 - ¥0.00/L`
  两格都是"看起来像 bug 的 0"。混动车不受影响（有汽油记录），纯油正常。
- **建议**：按 `vehicle.energyType` 分支——电车把这两格换成"总充电量 kWh"和"电价范围 ¥/kWh"（`getMinUnitPrice(vehicleId, electric)` 已经支持按类型查）。

### [M3] 自动"导前备份"缺少 `discount` 字段

- **位置**：`lib/features/export/providers/export_provider.dart:410-430`（`_writePreImportBackup`）vs `:79-95`（`exportToJson`）
- **证据**：
  ```
  exportToJson 的记录 map        :  'amount', 'discount', 'unit_price', ...
  _writePreImportBackup 的记录 map:  'amount',            'unit_price', ...   ← 少了 discount
  ```
- **影响**：这是"导入选错文件时的唯一回滚手段"。用它恢复后所有优惠变 0（`amount` 实付仍在，总额不受影响，但机显金额无法还原）。B1 修好后这条会真实暴露。
- **建议**：改成复用同一个序列化函数（`_recordToJson(r)`），彻底消除两份 map 漂移的可能。
