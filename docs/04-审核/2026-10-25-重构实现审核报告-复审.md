## 三、Major

### [MA1] 记录列表顶部"快速统计"仍把升和 kWh 相加（混动车显示无意义数字）

- **位置**：`lib/features/records/presentation/records_screen.dart:117-128`、`:143-165`
- **证据**：
  ```dart
  117:  double totalCost = 0;
  118:  double totalFuel = 0;
  119:  for (final r in records) {
  120:    totalCost += r.totalPrice;
  121:    totalFuel += r.fuelAmount;        // ← 不区分 energyType
  122:  }
  123:  final avgPrice = totalFuel > 0 ? totalCost / totalFuel : 0.0;

  143:  String _quantityUnit(model_vehicle.Vehicle? v) {
  144:    switch (v?.energyType) {
  147:      case 'hybrid':
  148:        return '';                    // ← 混动单位是空串
  ```
- **原因**：M2 只修了"每条卡片的油耗"，`_buildQuickStats` 是同一页面里的另一处汇总，没跟着改。
- **影响**（混动车主，一眼就看到）：
  - 顶部显示 `总能耗 1234`（无单位），实际是 `升 + kWh` 的加法，量纲不同，数字无意义；
  - `均价` = 总花费 ÷ (升+kWh)，得到"元/混合单位"，也不成立；
  - 纯电、纯油车不受影响（列表里只有一种能源），所以只在混动上暴露——正好是新功能。
- **建议**：混动车顶部改为两列（`油 X L / 电 Y kWh`，均价各自算），或干脆在混动上隐藏"总能耗/均价"这两格，只留记录数/总花费。参考 `_quantityLabel` 已有的分支写法，改成返回 `(label, unit, sum)` 三元组按类型累加。

### [MA2] 迁移备份会覆盖唯一的原始备份；而迁移本身不在事务里

- **位置**：`lib/data/database/migration_backup.dart:39-56`；`lib/data/database/app_database.dart:36-46`；drift 侧 `drift-2.21.0/lib/src/runtime/api/db_base.dart:132-135`
- **证据**：
  ```dart
  // migration_backup.dart
  39:  final base = dbFile.path;
  40:  String? backupMain;
  41:  for (final suffix in ['', '-wal', '-shm']) {
  44:      final dst = '$base$kPreMigrationBackupSuffix$suffix';
  45:      await src.copy(dst);          // ← 无条件覆盖
  ```
  ```dart
  // drift-2.21.0/lib/src/runtime/api/db_base.dart:132-135
  } else if (details.hadUpgrade) {
    final migrator = createMigrator();
    await _resolvedMigration.onUpgrade(         // ← 外面没有 transaction 包裹
        migrator, details.versionBefore!, details.versionNow);
  ```
- **原因**：备份文件名固定、无"已存在则跳过"；而 `onUpgrade` 里 11 步 `customStatement` 是逐条自动提交的（drift 不包事务）。
- **影响**（正是备份要防的那个场景）：
  1. 第一次启动：`zhiji_oil.db`（v3，原始）→ 备份成 `*.pre-v4.bak`（好快照）；
  2. 迁移第 6 步失败 → 库已变成"表已改名、2 列已改名、`user_version` 仍 = 3"的半迁移状态，App 打不开；
  3. 用户重开 App → `_readUserVersion` 仍读到 3 → **把半迁移的库覆盖到 `*.pre-v4.bak` 上**；
  4. 此时"原始好快照"已经不存在了，而这个 App 没有云端。
- **建议**（两条都做，各 5 行）：
  1. 备份前判断 `dst` 是否存在，存在则跳过（或文件名带时间戳，只保留第一份）；
  2. 把 `_migrateToV4()` 整段用 `await transaction(() async { ... })` 包住 —— SQLite 的 DDL 是事务性的，这样迁移要么全成、要么原样回滚，配合幂等重跑就是真的安全。
- **验证方法**：在迁移中间人为 `throw`，重开 App，检查 `*.pre-v4.bak` 的行数与首次备份是否一致（这是复审最想看到的那条测试，与 9.5 同源）。
