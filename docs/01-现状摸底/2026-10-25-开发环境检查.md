## 三、踩到的坑（按发生顺序）

### 坑 1：`pub get` 卡 460 秒后失败——报 `Cannot open file ...pub-packages`

**现象**
```
Cannot open file, path = '...\Pub\Cache\git\flutter_packages-73276ef3d74c78d7c6f4b8558bef08b04961b9d5\.git/pub-packages'
(OS Error: 系统找不到指定的路径。, errno = 3)
```

**本质**：上次下载中断留下的残目录。真正的报错被这层掩盖了。

**处置**：删掉 `Pub\Cache\git\flutter_packages-*` 残目录后重试。

### 坑 2（真正的根因）：`Filename too long`

重试后暴露真实原因：

```
error: unable to create file packages/pigeon/platform_tests/.../AlternateLanguageTestPlugin.java: Filename too long
fatal: cannot create directory at 'packages/webview_flutter_platform_interface-v2.10.0/...': Filename too long
```

**本质**：鸿蒙适配依赖来自 `atomgit.com/openharmony-tpc/flutter_packages`，仓库里有大量深层嵌套的 Java 路径，超过 Windows 默认的 260 字符上限。

**为什么值得记**：这类报错信息完全没提"路径太长是 Windows 限制"，只反复说 `Filename too long`，很容易被误判成磁盘/权限问题。

**处置**（一条命令，用户级配置，不需要管理员）：
```
git config --global core.longpaths true
```
- 系统注册表 `HKLM\SYSTEM\CurrentControlSet\Control\FileSystem\LongPathsEnabled` 实测**本来就是 1**（系统支持长路径）
- 只是 git 自己没开这个开关
- 开完后实测能创建 374 字符深的目录

### 坑 3：首次 Gradle 构建耗时 38.7 分钟

**不是卡死**，是在下载 Flutter 引擎的 debug AAR（`io.flutter:arm64_v8a_debug` 等），从 Google 的 CDN 拉，国内很慢。

**证据**：构建过程中 `~/.gradle/caches` 从 0 涨到 2 GB，Java 进程 CPU 时间持续增长。

**预期**：第二次构建会快得多（依赖已缓存），估计 1–3 分钟。
