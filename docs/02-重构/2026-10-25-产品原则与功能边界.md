# 智记油耗 · 产品原则与功能边界（2026-10-25 定）

> 本文是**不可轻易更改的基线**。任何功能增删、技术选型，都要先过这一关。

---

## 一、三条原则（作者原话）

1. **免费**
2. **数据本地**
3. **不用登录，开箱即用**

## 二、为什么做这个 App（初心）

作者原话，两条：

1. **小熊油耗被工信部通报了，读取用户数据**
2. **打开使用时到处都是广告**

所以这个项目不是"再做一个油耗 App"，而是"做一个不这么干油耗 App"。

---

## 三、明确不要的功能（已定，不再讨论）

| # | 不要的功能 | 理由 |
|---|---|---|
| 1 | 广告 | 初心之二 |
| 2 | 会员付费 | 与"免费"原则冲突 |
| 3 | 社交（排行榜 / PK） | 需要服务器 + 运营，且与"数据本地"冲突 |
| 4 | 云端数据备份 | 与"数据本地"原则冲突。**注意：本地数据备份（导出 JSON/Excel）必须保留** |
| 5 | 账号体系 | 与"不用登录"原则冲突，且需要服务器 |

**共同点**：这 5 项要么需要后端，要么需要收集用户数据。只要守住这三条原则，它们就自然被排除。

## 四、合规体检：原则在代码里成立吗（2026-10-25 实测）

### 4.1 智记油耗

| 检查项 | 结果 |
|---|---|
| Android 声明权限 | **0 个**（`android/app/src/main/AndroidManifest.xml` 里一条 `uses-permission` 都没有） |
| 鸿蒙声明权限 | **1 个**：`ohos.permission.INTERNET` ⚠️ |
| 依赖中的网络库 | **0 个**（无 http / dio / web_socket 等） |
| 源码中的网络请求 | **0 处** |

**结论：Android 侧零权限，物理上无法联网上传任何数据。** 这是最硬的合规证明——不是"承诺不上传"，而是"没有权限上传"。

### 4.2 对比：小熊油耗（同一次实测）

| 项 | 小熊油耗 | 智记油耗 |
|---|---|---|
| 声明权限总数 | **38 个** | 0 个（Android）/ 1 个（鸿蒙） |
| 其中敏感/隐私类 | 16 个 | 0 个 |
| 读取已安装应用列表 | ✅ `QUERY_ALL_PACKAGES` | ❌ |
| 读设备信息 | ✅ `READ_PHONE_STATE` | ❌ |
| 定位 | ✅ `ACCESS_FINE_LOCATION` / `COARSE` | ❌ |
| 广告标识符 | ✅ `AD_ID` | ❌ |
| 允许安装其它应用 | ✅ `REQUEST_INSTALL_PACKAGES` | ❌ |
| 相机 | ✅ `CAMERA` | ❌ |
| 读写外部存储 | ✅ `READ/WRITE_EXTERNAL_STORAGE` | ❌ |

**小熊油耗的 `QUERY_ALL_PACKAGES`（看你装了哪些 App）+ `READ_PHONE_STATE`（读设备标识）+ 定位 + `AD_ID`，正是超范围收集个人信息的典型组合**——这与作者看到的工信部通报方向一致。

### 4.3 需要修的一个漏洞

鸿蒙侧声明了 `ohos.permission.INTERNET`，但代码里没有任何网络调用。

- **判断**：这是 Flutter-OH 模板默认带的，属于多余声明
- **建议**：删除。理由是把"零权限"这件事做彻底，也让审核和用户一眼看到干净
- **风险**：删除后需重新构建验证鸿蒙版能正常跑（本地功能不需要网络权限）

## 五、待讨论：功能边界扩展到哪

已确定不要的 5 项之外，小熊油耗还有这些**纯本地可实现**的能力：

| 功能 | 纯本地可做 | 一年用几次（作者自评） | 实现成本 |
|---|---|---|---|
| 加油站名称管理 | ✅ | 每次加油 | 极低 |
| 费用账本（保险/停车/洗车/罚款） | ✅ | 十几次 | 低 |
| 保养记录（大小保养） | ✅ | 2–3 次 | 低 |
| 提醒（按天数/按公里） | ✅ 但需通知权限 | 设一次长期用 | 中 |
| 支出占比 / 年度报表 | ✅ | 年底一次 | 中 |
| 换肤 | ✅ | 新鲜几天 | 低 |
| 充电 / 混动记录 | ✅ | **要做**（2026-10-25 改定：油车越来越少，混动纯电越来越多） | 中 |

### 三种扩展档位

| 档位 | 包含 | 定位 | 工作量 |
|---|---|---|---|
| **A. 只做加油** | 现有 6 个模块不变 | 纯粹的油耗记录器 | 0（本次重构不扩功能） |
| **B. 用车账本** | A + 保养 + 费用 | 一台车一年的完整账本 | 各加一张表 + 一个录入弹窗 |
| **C. 完整助手** | B + 提醒 + 报表细分 | 接近商业 App 的本地版 | 需要通知权限与定时任务 |

### 判断依据

- **"开箱即用"的代价**：每多一类记录，就多一个录入入口。功能越多，第一眼越复杂。
- **保养和费用与加油记录同构**（都是"日期 + 金额 + 备注"），能复用现有架构，边际成本低。
- **提醒需要通知权限**，这是本项目目前唯一会申请的权限，一旦引入，"零权限"这个卖点就有了例外。

### 连带影响（容易被忽略，也是审查重点）

1. **能耗算法有缺陷要修**：现在只取单条记录的加油量，中间未加满的油量被丢弃 → 油耗被低估；平均油耗用的是算术平均 → 结果偏大
2. **统计口径**：两个花费数字（首页加油花费 / 统计页全部花费），两个成本指标（能耗成本/公里 vs 用车总花费）
3. **数据迁移**：`schemaVersion` 3 → 4，要改表名、改 4 个列名、加 2 列、加 1 张表，且**现有 `onUpgrade` 用空 `catch` 吞异常，必须删**
4. **导出导入**：现有备份是 `version:"1.0"` + 记录嵌套在车辆下；导入无事务、不还原默认车、文件落在应用私有目录用户找不到
5. **算法必须三处统一**：统计页 / Excel / 首页看板共用同一个计算函数

### 需要保持的原则

**不申请任何新权限**。这意味着以下功能都不能做：

- 拍照/上传发票照片（需要相机或相册权限）
- 定位记录加油站（需要定位权限）
- 任何形式的联网（需要网络权限）

## 八、"按上架标准写代码"的具象化

不上架，但标准不降。具体是这 10 条，每一条都能验收：

| # | 标准 | 现状 |
|---|---|---|
| 1 | **权限最小化**：只申请必需的权限 | ✅ 已达成（Android 0 个） |
| 2 | **隐私声明**：仓库里放一份 `PRIVACY.md`，声明"不收集任何信息" | ✅ `PRIVACY.md` 已存在，含自查方法 |
| 3 | **release 签名**：不能只出 debug 包 | ✅ 自签 release 证书（`CN=Zhiji Oil Consumption`，`apksigner verify` 实测通过） |
| 4 | **版本号规范**：`versionName` 语义化 + `versionCode` 递增 | ✅ `1.0.0+3`；split 包 arm64 = versionCode **2003**。真源 = `pubspec.yaml`，脚本自动读取 |
| 5 | **升级不丢数据**：数据库迁移必须可靠，老版本数据能平滑升级 | ✅ 迁移测试 2 个（含幂等）+ 迁移前自动备份 + 迁移包进事务 |
| 6 | **不吞异常**：出错要让用户看见并说清原因，不能 `catch` 完返回空 | ✅ 迁移与导入路径已清空静默 catch（仅保留"读不到车辆就按油车处理"这类兜底，均带注释） |
| 7 | **静态检查零警告**：`flutter analyze` 干净 | ✅ `No issues found!`（生成文件已在 `analysis_options.yaml` 中排除） |
| 8 | **核心逻辑有测试**：能耗公式必须有覆盖 | ✅ 14 个用例（能耗 11 + 迁移 2 + 启动 1）；**导入导出仍无自动化测试** |
| 9 | **数据可恢复**：导出文件能完整还原（这是唯一的数据保险） | ⚠️ 导入手动验过 V1/V2 两种格式，**但没有自动化测试** |
| 10 | **显示适配**：小屏/大屏/字体放大/深色模式都不错版 | ⚠️ 有深色，未验证其他 |

**为什么不上架还要按这个标准**：开源项目被人下载就是"发布"，出了数据丢失问题一样有人骂。而第 5、6、9 条正好是这个 App 最要命的地方——它存的是用户几年的加油记录，**丢了就是丢了，没有云端可以找回**。
