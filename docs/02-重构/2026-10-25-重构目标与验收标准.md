### 项 2 · 能耗算法修正（优先级高）

- [ ] **2.1 区间求和**
  - 现状：只取单条记录的加油量，中间未加满的油量被丢弃 → 油耗被低估
  - 动作：`sum(锚点区间内同能源类型的 quantity) / 里程差 × 100`
  - 验收：加满 → 未加满 20L → 加满 15L，里程差 500km，结果必须 = `(20+15)/500×100 = 7.0`
- [ ] **2.2 加权平均**
  - 现状：各段比值的算术平均（短途权重大 → 结果偏大）
  - 动作：`总能耗 ÷ 总里程 × 100`，且分子分母都锁在"第一个锚点到最后一个锚点"之间（详见规格 §5.2）
  - 验收：两段（100km/10L 与 900km/72L）加权结果 = `82/1000×100 = 8.2`，不是 `(10+8)/2=9.0`
  - 追加断言：分段相加 与 直接聚合 结果必须相同
- [ ] **2.3 Excel 与统计页共用同一算法**
  - 现状：Excel 用未过滤的相邻记录配对，统计页要求 `isFull`，两边数字不同
  - 动作：抽 `ConsumptionCalculator` 供三处复用
  - 验收：同一辆车，Excel 油耗列与统计页数字一致
- [ ] **2.4 录入校验（复审补回）**
  - 现状：录入弹窗不做任何合理性检查，录错也不提醒
  - 动作：保存前检查三件事，**只提示不硬拦**（允许"确认仍要保存"）：
    1. 里程小于上一条 → "这条的里程比上一条少，是不是填错了？"
    2. 单价 > 数量 → "单价看起来像加油量，是不是填反了？"
    3. 日期早于上一条 → "日期比上一条早，确认吗？"
  - 验收：单价填 40、加油量填 8 → 弹出"填反了"提示；点确认后正常入库并参与统计
  - 为什么重要：这是"油耗算不准"的**源头**，数据错了后面算得再精确也没意义
